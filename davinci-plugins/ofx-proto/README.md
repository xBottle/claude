# Прототип 2: настоящий OFX-плагин (C++)

## Что это
Компилируемый OFX-плагин — тот же класс инструмента, что и Procedural CRT
на sh4rkk.com. `CRTProtoPlugin.cpp` — не Fusion-нода, а отдельный бинарник
`.ofx`, который Resolve грузит как сторонний плагин (как Boris FX, Neat Video
и т.п.).

Ключевая часть — `CRTProtoInteract` — кастомный overlay, который рисует свои
виджеты **прямо поверх вьюера**, а не через стандартную панель Inspector.
Именно так делают "не-нативный" вид, который ты видел на сайте.

## Важно: этот файл нельзя собрать в облачной сессии
Здесь нет macOS/Xcode/Metal — это Linux-контейнер. Файл нужно перенести
на твой Mac и там собрать.

## Что нужно на Mac, чтобы собрать
1. **Xcode** + Command Line Tools (`xcode-select --install`).
2. **OpenFX SDK** (`openfx` + `openfx-supportext`) — открытый, на GitHub
   у AcademySoftwareFoundation: `github.com/AcademySoftwareFoundation/openfx`.
   Это заголовки `ofxsImageEffect.h` и т.д., которые подключает наш `.cpp`.
3. Собрать как **bundle** (`.ofx.bundle` на macOS, структура как `.app`):
   ```
   CRTProto.ofx.bundle/
   └── Contents/
       ├── Info.plist
       └── MacOS/
           └── CRTProto.ofx   (Mach-O dylib, universal x86_64+arm64)
   ```
4. Положить бандл в `/Library/OFX/Plugins/` (общий) или
   `~/Library/OFX/Plugins/` (для своего пользователя).
5. Перезапустить Resolve → эффект появится в списке OFX-эффектов на
   странице Edit/Color (в зависимости от `addSupportedContext`).

## Дальше по-честному
- Реального CRT-рендера тут нет — только заглушка (полосы по X), чтобы
  проверить, что плагин вообще собирается, грузится и применяется к клипу.
- Оверлей `draw()` пустой (только заглушка `return true`) — рисование своих
  виджетов через OpenGL immediate mode нужно дописывать отдельно, это
  отдельный кусок работы (шрифты, хит-тесты мышью, драг).
- Порт логики CRT Pro (129 контролов) на GPU-шейдер (Metal через OFX GPU
  render suite) — отдельный большой этап, не за один присест.

## Честная оценка трудозатрат
Довести этот прототип до уровня "как на сайте" (полноценный кастомный UI +
перенесённая логика CRT Pro на шейдер) — это, по объёму, недели работы даже
для человека, который каждый день пишет C++/OFX, потому что:
- нет живой отладки без Mac под рукой у меня — весь цикл "собрал → упал →
  чиню" ты делаешь сам, я только пишу код по описанию ошибки;
- OpenGL/интеракт-рисование виджетов руками — самая нудная часть, в
  Fusion-нодах (или в UIManager) этого просто не существует, там виджеты
  готовые;
- перенос уже готовой логики CRT Pro с Fusion-нод на шейдерный код — это,
  по сути, переписать эффект заново на другом языке.
